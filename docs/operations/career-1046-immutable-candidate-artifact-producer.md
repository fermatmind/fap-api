# Career 1046 immutable candidate artifact producer

This is a protected, manual-dispatch-only control-plane workflow. It first validates one successful Task 3B apply receipt, its GitHub artifact digest, exact control-plane SHA, active release identity, 1016 receipt-covered matching publication/index rows, and the immutable database-state hash. It streams the checked-in, checked-out control-plane producer together with its canonical JSON, immutable-generator, and reconciliation dependencies to the exact active release; that release supplies only the Laravel bootstrap and MySQL read-only context, so a historical Task 3B release need not contain later producer code.

The producer reuses `Career1046ImmutableCandidateGenerator`; it emits exactly one runner-side file, `career-1046-immutable-candidate.json`, uploaded as `career-1046-immutable-candidate`. The file contains one deterministic 1046-slug/2092-locale-row generation, excludes both frozen forbidden slugs, keeps sitemap/llms/Search closed, and carries the Task 3B binding in the candidate receipt. Task 5 validates this exact one-file artifact contract.

Unexpected producer failures are classified at six fixed boundaries: ledger (including the production database-state reconciliation read), projection, detail bundle, resource transform, generator, and serialization. Each boundary emits only its allowlisted `CANDIDATE_*_STAGE_FAILURE` code; raw exceptions, SQL, payloads, slugs, paths, topology, and secrets remain absent. Existing fixed authority and zero-write failure codes remain unchanged.

The outer lifecycle is independently fail-closed at initialization, read-only transaction, audit initialization, and audit finalization. The streamed runner is a fresh PHP process rather than an `artisan` entrypoint, so it loads the active release's non-symlinked `vendor/autoload.php` before requiring `bootstrap/app.php`; a missing or invalid autoloader fails closed as `APPLICATION_AUTOLOAD_INVALID`. MySQL then starts one atomic `START TRANSACTION READ ONLY` transaction after the database/cache auditors are installed; this removes the former split driver boundary between `SET TRANSACTION READ ONLY` and Laravel's later transaction open. Unexpected outer failures emit only the corresponding fixed lifecycle code, so the generic control failure is no longer reachable.

The production entrypoint validates the frozen 30 + 1016 target and the Task 3B database-state receipt before ledger generation. Task 3B is the exact DB authority for the 1016 delta rows, so only that frozen delta is passed to `CareerFullReleaseLedgerService` as the pre-activation trusted batch with cache writes disabled. The exact 30 baseline ledger rows are read through `CareerGenerationAuthorityLoader::loadStrict()` from the still-active generation and replace only the corresponding recomputed rows. Missing, duplicate, or non-exact active baseline authority fails closed. This preserves the current root until Task 6 instead of incorrectly reclassifying baseline rows as a new batch. It does not consult historical promoted-execution files as delta candidate authority: doing so would make Task 4B depend circularly on a promotion that Tasks 5–7 have not performed yet.

The merged ledger still recomputes every delta cohort, blocker, count, target, and forbidden gate from production authority. Before any detail build, the projection must be the exact 1046-slug/2092-locale pair set and every item must be published, route-enabled, indexable, and release-gate-passed; otherwise it emits only `CANDIDATE_PROJECTION_AUTHORITY_INCOMPLETE`. The transaction installs fail-closed query and cache mutation auditors before reading authority: every observed application query must be `SELECT`, and any attempted cache write, forget, or flush aborts the candidate. The emitted producer authority records the observed query count, the exact `select` verb set, and an observed zero cache-write count; these are execution evidence rather than fixed declarations.

No workflow is triggered by push, schedule, or another workflow. The control does not deploy, migrate, write database/CMS/cache/artifact-tree/pointer state, warm, publish, alter sitemap/llms, or submit URLs. Merging it does not authorize dispatch or production execution.
