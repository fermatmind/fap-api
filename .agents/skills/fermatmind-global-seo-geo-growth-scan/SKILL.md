## Purpose

Route FermatMind SEO/GEO scans to the smallest correct role set while preserving backend/CMS authority, evidence quality, private-result boundaries, and one-scope follow-up work.

## When to use

- Weekly SEO/GEO opportunity scans.
- Monthly growth portfolio reviews.
- Category breakthrough planning for MBTI, Big Five, RIASEC, Career, articles, or another approved surface.
- Cross-repository scans that combine search data, technical authority, content quality, CMS/API stability, and conversion.

## When not to use

- Do not use as production deploy readiness or AppSec red-team replacement.
- Do not use to publish CMS content, change database state, promote indexability, submit GSC, request indexing, or deploy.
- Do not use for a narrow implementation task that already has a dedicated repository skill.

## Required reading order

1. Repository `AGENTS.md`.
2. `backend/docs/seo/growth-role-playbooks/evidence-output-contract.md`.

## Preflight

- Confirm repositories, branches, dirty worktrees, current date/timezone, locale, country, device, and analysis windows.
- Read current code and docs before accepting historical chat assumptions.
- Confirm current backend/CMS/public API authority and deployed revisions when runtime evidence matters.
- Apply the local heavy-test concurrency guard before running any full validation.
- Classify each source as verified, observed, inferred, unknown, or blocked.

## Current strategy anchors

- Internal target: compete for top-three Chinese/English visibility; never guarantee ranking.
- Positioning: free professional assessments with free complete result pages.
- Priority: L1 MBTI, L2 Big Five, L3 articles/topics/career recommendations/non-core tests.
- Current Chinese MBTI baseline: 32 profiles + 20 comparisons are a governed 52-URL cohort. Verify current runtime and search evidence; do not plan them as missing by default.
- Frontend renders product code and backend authority. It must not add CMS-backed editorial fallback.

## Standard execution

1. Select mode and role files.
2. Build source inventory and data-quality verdict.
3. Map query families to business surfaces and primary owner pages.
4. Check technical authority and public stability before content expansion.
5. Analyze search opportunity, content/entity gap, and funnel value.
6. Separate facts, hypotheses, unknowns, and blockers.
7. Produce the shared output bundle from `evidence-output-contract.md`.
8. Convert recommendations into one-owner, one-scope PR or CMS content-package cards.
9. Keep production/CMS/search mutations as separately controlled follow-ups.

## Handoffs

- Content research/package planning: `.agents/skills/fermatmind-seo-research-content-planning/SKILL.md`.
- CMS/import/promotion review: `.agents/skills/fap-api-cms-publish-review/SKILL.md`.
- PR lifecycle: `.agents/skills/fermatmind-pr-train/SKILL.md` or an ad-hoc scoped PR under repository rules.
- Deployment/SRE/security: use the dedicated deploy or security skill; this skill supplies evidence only.

## Minimum output

- Run metadata and source-quality table.
- Surface/locale scorecard.
- Query-page owner and opportunity matrix.
- Technical/stability/content/funnel findings with evidence state.
- 7/30/90 day roadmap.
- Single-scope PR/content-package cards.
- Blocked/unknown ledger.
- Explicit statement of mutations not performed.

## Hard stops

- Stop numeric prioritization when search/analytics quality gates fail.
- Stop URL expansion when owner, authority, indexability, originality, or claim boundaries are missing.
- Stop and isolate private URL exposure, false public indexability, or unsafe public claims.
- Never treat schema, sitemap, llms, rankings, or competitor claims as proof of content authority.
- Never infer production authorization from a scan request.
