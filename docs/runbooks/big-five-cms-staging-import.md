# Big Five CMS Staging Import Runbook

This runbook governs the first non-production CMS write attempt for the Big Five
public personality content assets. It is an operator protocol, not an approval
to import, publish, index, deploy, or release SEO/GEO surfaces.

## Scope

In scope:

- Staging or development CMS import only.
- Big Five CMS draft package generated by the backend-authoritative PR train.
- Draft/review content rows targeting `personality_public_content_assets`.
- Import verification, rollback handle capture, and preview/readback QA.

Out of scope:

- Production CMS import.
- Publishing any page.
- Flipping `index_eligible`, `sitemap_eligible`, or `llms_eligible`.
- Emitting runtime JSON-LD for the imported rows.
- Adding Big Five rows to sitemap, `llms.txt`, `llms-full.txt`, search
  submission, canonical indexation release, or revalidation queues.
- Triggering staging deploy waits, manual deploy, production deploy, database
  migrations, scheduler activation, or frontend fallback content.

- Preview/readback planning summary:
  `generated/big-five-cms-preview-readback-qa/readback_qa_report.md`

The dry-run evidence must show all of the following before a staging write is
considered:

- `ok=true`
- `row_count=42`
- no `/zh/big-five` or `/en/big-five` short-route residue
- no committed writes in the dry-run report
- no publish/index/sitemap/llms release attempt
- FAQ dedupe policy active, with top-level `faq` as the only structured FAQ
  source
- all rows default to noindex, not public, not index eligible, not sitemap
  eligible, and not llms eligible

## Required Authorization Packet

Before `BIG5-CMS-STAGING-WRITE-IMPORT-10` may run a staging/dev write, the
operator must provide an exact authorization packet in the thread or linked
approval record.

Required fields:

- target environment: `staging` or `dev`
- target backend host or connection alias
- target database connection name
- exact git SHA that contains the importer command
- exact package path
- package SHA-256
- import mode: staging/dev draft write only
- allowed content type set
- expected row count: `42`
- confirmation that production import is not authorized
- confirmation that publish/index/sitemap/llms/JSON-LD runtime release is not
  authorized
- rollback handle strategy
- operator name or handle
- UTC approval timestamp

Required confirmation phrase:

```text
I authorize Big Five CMS staging/dev draft import only. No production import, publish, indexability, sitemap, llms, JSON-LD runtime, deploy, or search release is authorized.
```

If any required field is missing, the write-import PR must stop before running a
write command.

## Preflight Commands

Run these checks from the repository root before any staging/dev write attempt:

```bash
python3 -m json.tool generated/big-five-content-polish/cms-import-draft.polished.json >/dev/null
python3 -m json.tool generated/big-five-cms-import-dryrun/dryrun_report.json >/dev/null
python3 -m json.tool generated/big-five-cms-preview-readback-qa/readback_qa_report.json >/dev/null
ruby -e "require 'yaml'; YAML.load_file('docs/codex/pr-train.yaml'); puts 'yaml ok'"
python3 -m json.tool docs/codex/pr-train-state.json >/dev/null
git diff --check
```

Run the no-write importer planner against the exact package:

```bash
cd backend
APP_ENV=testing DB_CONNECTION=sqlite DB_DATABASE=':memory:' \
  php artisan personality:big-five-cms-import-draft-dry-run \
  --package=../generated/big-five-content-polish/cms-import-draft.polished.json \
  --dry-run \
  --json
```

This command is no-write only. Its `--write` option intentionally fails closed
in the current implementation. A later staging write PR must either add a
controlled staging/dev-only write path with tests, or stop if no such command
exists.

## Staging Write Guardrails

A staging/dev write command must fail closed unless all guardrails are true:

- environment is explicitly `staging` or `dev`
- package SHA matches the authorized SHA
- row count is exactly `42`
- all rows map to `/zh/personality/big-five/...` or
  `/en/personality/big-five/...`
- all rows remain draft/review content after import
- all rows remain noindex
- `is_public=false`
- `index_eligible=false`
- `sitemap_eligible=false`
- `llms_eligible=false`
- `published_at=null`
- runtime JSON-LD is suppressed
- sitemap and llms enumeration remain blocked
- FAQ body sections are not rendered as a second FAQ module

The write command must reject:

- production environment names or production database connections
- missing authorization packet fields
- package SHA mismatch
- row count mismatch
- old short Big Five route roots
- private result/order/share/payment/account URLs
- token-like query parameters
- publish flags
- indexability release flags
- sitemap or llms release flags
- JSON-LD runtime release flags

## Rollback Handle

The staging/dev write PR must record a rollback handle before or during import.
Acceptable rollback handles include:

- import batch id
- per-row previous revision ids
- pre-import export file
- staging database snapshot id
- deterministic delete criteria for the import batch

Rollback must restore the pre-import staging/dev state without touching
production. The rollback command or manual procedure must be recorded in the PR
body and in generated evidence.

## Post-Write QA

After a staging/dev write succeeds, run readback QA in a separate PR:

- confirm all `42` imported rows are readable in preview mode
- confirm public API draft/readback payload shape
- confirm FAQ appears from the top-level `faq` field only
- confirm body FAQ sections are not rendered as a duplicate FAQ module
- confirm all rows remain noindex and not public
- confirm sitemap, llms, and JSON-LD runtime remain blocked
- confirm English rows remain draft-only unless separately approved
- confirm Chinese rows remain CMS-review gated until manual review approval

## Publish and SEO Release Gates

Publishing and SEO/GEO release are separate gates:

- `BIG5-CMS-PUBLISH-GATE-12` may proceed only after CMS manual review approval.
- English pages remain draft unless the operator explicitly approves them.
- `BIG5-SEO-DISCOVERABILITY-RELEASE-13` may proceed only after publish gate
  completion and explicit release authorization.
- Sitemap, llms, JSON-LD runtime, canonical indexability, and search release
  must not be combined with staging write import.

## Stop Conditions

Stop immediately if:

- target environment is production or ambiguous
- authorization packet is incomplete
- package SHA does not match
- dry-run evidence is missing or failing
- a command would publish, index, release sitemap/llms, emit JSON-LD runtime, or
  submit search URLs
- rollback handle cannot be captured
- local checks fail and cannot be fixed in scope
- GitHub required checks fail
- repo state is dirty and cannot be isolated
