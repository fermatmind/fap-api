# SEO Council 运营交接规则

本文件是 **SG-OPS 的现行入口**。既有角色 playbook、通用周/月 runbook、MAP 资产和任务交接提供各自领域证据；专家团的状态、选择和交接以本入口为准，不另建队列或生产记录。

本规则用于现有 Ops Agent Council、SEO 工作台、Mission、自然周卡和发布流水线。它不启用新的任务、模型、工具、通知、业务写入或自动发布权限。以当时生产 `REVISION`、正式回执和页面读回为准；历史演示、受控验收和当前排序预览不能代替自然运行。

## 责任与输入

| 责任方 | 当前职责 | 交接边界 |
| --- | --- | --- |
| M1：GSC 数据与运行 | 按已授权自然调度只读核 GSC 来源、完整窗口、数据质量和运行状态。 | 输出来源时间、数据最大日期、正式回执及 HOLD 原因；数据未到不填零、不补同步。 |
| M2：URL Truth 与 D1 | 对账公开 authority、Truth 和 current binding 的身份及版本一致性，兼核聚类去重和 D1 观察。 | 输出实际分母、差异及对应权威版本；缺少来源时保持 HOLD，不用历史数量替代。 |
| M3：隐私与 Policy | 核证据过期、私有路径负向检查、权限和版本漂移。 | 安全或权限异常立即交唯一运营者处理；Council 本身不修复、不开放工具。 |
| 自然周卡 | 周四 13:45 UTC（北京时间 21:45）运行确定性发现、校验、去重和选择。 | 仅写 SEO 规划记录。每次最多创建或刷新 5 张卡，正式选择默认最多 3 张；不足不补。 |
| Codex | 复核来源、页面和产品事实，提出单页假设；在获授权范围内实现、聚焦验证、正常上线、自然验收与清理。 | 复用仓库 direct-main、精确 SHA 流水线；分析不能冒充 Council 回执，具体受控内容/权限边界仍以当前仓库契约为准。 |
| Pro | 提供专家意见和反例检查。 | 建议须由当前权威和数据重新核实，不是生产事实、权限或发布授权。 |
| 唯一开发者／运营者 | 处理必需业务选择、外部账户授权和不可逆风险决策，承担受控内容审校与效果复盘。 | 决定绑定精确目标和版本；已授权的普通实现与自动部署由 Codex 连续交付，没有正式写入口时只记“暂存／待正式写入”，不得称已入库。 |

## 每日、每周、每月交接

1. **每日按既有调度看异常。** 先确认生产 `REVISION`、调度授权、`latest_natural` 与 `latest_controlled` 的时间和回执哈希，再看 M1/M2/M3 的 `execution_state`、`business_result` 与 Trace。执行失败、积压或证据不可读与已执行但业务 HOLD 分开记录；预期 GSC 延迟等待下一自然窗口。生产事故、安全泄露、权限越界和版本读回不一致立即升级给对应原任务及唯一运营者。
2. **每周复核真实周卡、已有 MAP 机会、选择与积压。** 周卡只接受真实 scheduled 结果：核两类周回执的 schema、hash、ISO 周、`scheduled_for`、实际 release SHA、`generation_summary` 和正式选中版本；逐项区分 `scan_rows`、信号候选、按 `canonical_url_hash|locale` 去重的页面、证据校验、合格页、创建/刷新卡、HOLD、上限未处理页。`current_ranking_preview` 只是预览，不能当成本周正式选择。零张且双回执合法时记“自然运行完成、出卡链未证明”，查过滤原因，等下一自然窗口。已有 MAP 机会可独立复核和选择，无须等待周卡；不得冒充自然周卡记录。
3. **复核、选择并交接。** 同一目标、语言和假设去重，合并 MAP 与周卡来源但保留每个精确版本；不同假设不因 URL 相同就合并。只接受公开合格目标和新鲜、完整、可比的正式来源。对每项记录来源版本、目标 URL/语言/页面族/正文权威版本、证据哈希、卡及 `selection_revision`、现有 ledger/current pointer、建议动作、交付物、验收条件、依赖、成本/风险、责任人、到期时间、回退边界和“执行／暂缓／否决”理由。原始查询留在授权私有证据中。O3 没有真实受控写入口时仅暂存交接，不声称已入库。过期、版本失效或证据不足的建议先 HOLD，不能直接交付；规划卡的 `read_only_review` 与 `execution_allowed=false` 不授权发布。
4. **每月及每批成熟窗口复盘。** 保留实际发布 SHA 和 D0；仅在完整 D7、D14、D28 数据到达后按同口径比较页面与查询指标，记录同期发布和测量变更。选择保持、扩大、调整、延长观察或停止，并核事实是否过期。未发布的卡没有 D0，未成熟的数据没有效果结论。

交接状态最少包含：`未开始／进行中／待自然窗口／HOLD／已验收／条件未触发`、证据链接及时间、责任方、下一触发条件。`HOLD` 须写明缺少的来源或门禁；运行失败须保留失败 job/step 与正式回执。积压按可执行性、证据到期和风险排序；不因候选数量或预览分数绕过人工决定。四个自然周后逐窗复核运行、零卡、HOLD、失败和交接积压；四周无卡不能证明“周卡→发布→增长”。

## 状态、责任与下一动作

这些是既有字段的运营解释，不新增数据库状态或开关。每次同时记录授权、执行、业务结论和交付状态，禁止用一个“绿灯”覆盖其余维度。

| 状态 | 责任与下一动作 | 必需证据／通知条件 |
| --- | --- | --- |
| 未授权／门禁未通过 | Codex 定点核 `selected`、`acceptance_ready`、`source_accepted`、`end_to_end_accepted`、`run_allowed` 和 pause；唯一开发者处理必需外部权限或另行受控动作。 | 按真实身份核当前激活版本、门禁原因；不能把业务 HOLD 说成未授权，也不能以目录计划时间声称已启用。实际需要用户动作才通知。 |
| 等待自然窗口 | 原任务保留验收义务，沿用已有定时；窗口错过则等下一真实窗口。 | 发布 SHA、下一合法窗口、已有正式回执；不补跑、不 dispatch、不改旧时间。状态未变静默。 |
| 执行积压 | Codex 核可执行性、租户/来源范围、lease、队列与任务依赖，按风险及到期排序。 | 正式 backlog、owner、最旧时间和门禁；不能把未授权任务当可运行积压。持续恶化或影响交付时通知。 |
| 技术失败 | Codex 查实际 job/step、日志及失败路径；获授权的同范围缺陷用新 commit 正常交付。 | 错误、SHA、失败 operation 和最小复现；保留诊断。不盲重试、扩大权限或以新 gate 掩盖根因。真实失败通知，事故按已有自动 LKG 边界处置。 |
| 业务 HOLD／DENY | Codex 解释证据缺口、合法到期、数据延迟、版本漂移或真实风险，明确责任与解除条件。 | 冻结回执 schema/hash/来源版本及原因。真实安全风险失败关闭并立即通知；普通外部延迟等待，不能填零、延长 TTL 或复制旧证据。 |
| 合法零卡 | Codex 验双回执和生成摘要，记录自然执行完成；出卡业务验收保持未完成。 | 查询逐日覆盖与同步完整性分别证明；扫描页分母不能代表全站。无可行动变化静默，确证实现缺陷单独交付建议。 |
| 已选择／暂存 | 唯一开发者作必需业务选择，Codex 记录精确交接和实现前复核。 | 执行／暂缓／否决理由、精确版本、交付物、依赖、成本及回退；正式选择与排序预览分开。无写入口的 O3 仅暂存。 |
| 已交付／验收中 | Codex 分项跟踪实现、自动部署、线上读回、自然验收及资源清理。 | runtime 用同 SHA CI/staging/production/smoke；仅文档规则用 CI/deploy-skip。上线成功不能替代自然业务验收；全部适用验收和清理后通知完成。 |
| 效果待观察 | Codex 保留 D0 和并行变更，唯一开发者在成熟窗口复盘。 | 完整 D7/D14/D28、同口径基线、数据成熟度；未成熟只等候。证据改变决策时通知，不承诺增长。 |

每日只核异常及可行动变化，每周核候选/选择/积压，每月核内容事实时效及成熟效果。沿用既有定时，不新增重复自动化；原定时仍承载独立验收义务时不得因某一子项完成就暂停。模型、Tool Broker、业务写、通知、外部执行与自主发布继续保持各自原边界；不接 DeepSeek、不购买工具、不因本规则自动开权限。仓库正常流水线中已授权的独立采集不能冒充 Council 工具调用，反之亦然。

## 脱敏历史案例校验

- W40（2026-10-01）的真实双回执为零卡：58 页已校验、51 页查询日期不足、7 页 Truth 缺失或歧义。正确交接是“自然执行完成，业务出卡待验收”，不生成样例卡或放宽阈值。只记录聚合计数不能追认当时七个身份；需独立身份证据。
- 同一 W40 的 `scheduled_for=13:45:03Z` 与监控 `13:45:00Z` 精确比较会报告 `capability_expected_slot_mismatch`，而双回执 hash 可有效。正确动作是独立监控诊断，保留旧回执，不称生产部署失败；错误周次、错窗口、缺失、重复和 hash 损坏仍必须拒绝。
- M3 历史正式回执的 `STALE_EVIDENCE_HOLD` 与当前 `run_allowed=false` 可以同时存在。正确动作分别核证据生命周期及 end-to-end 门禁；读回快照不替代自然回执，也不以本文件授权重做受控验收。
- 单页改动即使已部署，也须保留其 D0、自然验收及 D7/D14/D28义务。没有正式受控写入口的 MAP/O3 建议只暂存；不制造 ledger、选择或发布记录用于演示。

## 当前权限和实现锚点

- `backend/bootstrap/app.php` 定义周卡自然窗口及 Council 调度；`backend/config/app.php` 的应用时区为 UTC。Council Mission 是否调度仍受 `seo_council.scheduler_enabled` 控制。
- `backend/config/seo_council.php` 默认关闭模型、Tool Broker 和通知；`SeoWeeklyPlanningReadService` 的权限投影将自然规划写与 GET/模型/工具/发布/实验/搜索提交分开。
- `SeoOpportunityCardGenerator` 定义来源门禁、去重键、最多 5 张卡和不可执行建议；`SeoWeeklyDecisionSelector` 定义默认 3 张及 `verified_zero`；`SeoWeeklyDecisionReceiptValidator` 与 `SeoWeeklyPlanningReadService` 验证正式双回执、卡版本和 ledger 后才展示“本周已选择”。
- `Platform12SystemHealthReadService` 将自然/受控证据、执行状态、业务结果和下一步分列。Ops 页面只读展示这些字段；本规则不能替代现场回执或生产权限核验。
